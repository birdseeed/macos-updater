## Version and route admission proposal

Keep the supported native version set **empty** until independent review and disposable proof accept an exact release commit, runtime/platform and route manifest. No minimum-version comparison or mutable manpage can confer support. Proposed support records bind Homebrew release/version, full source commit, relevant executable/interpreter/source digests, canonical prefix and account, assessed old/new official-cask source revisions and digests, artifact/dependency inventory, CLI/env contract, network policy, serialisation and cancellation protocol, and native evidence reference. Missing fields refuse.

The explicitly assessed candidate is Homebrew **4.6.17**, release commit [`aa278895809b4c079e560fb4fb9bf17e48cf65f1`](https://github.com/Homebrew/brew/commit/aa278895809b4c079e560fb4fb9bf17e48cf65f1). Assess only one official `homebrew/cask` token, one finite stable version and one app bundle from a straightforward archive. No concrete cask revision or native route has been admitted. Reject `latest`, self-updating/ambiguous versions, renamed/migrated tokens, language/options not fully assessed, packages, scripts, suites, plugins, helper installs and additional artifacts. Assess the installed predecessor as well as the proposed successor: upgrading removes old artifacts too.

## Shared operation and user experience proposal

PAT-2654/C7 must first supply bounded local ownership evidence without executing brew: canonical executable/prefix, owning UID/account, supported version/source binding, official token, installed receipt and bundle identity/version, freshness and complete scan status. Catalogue membership and display names cannot prove ownership. Writable receipts are not attestation. Multiple prefixes/accounts, stale or inconsistent receipts, moved apps, symlink/ancestor changes and uncertain version ordering hold. Installed inventory remains local; the explicit requested Homebrew download has separate network effects from catalogue matching.

Both UI surfaces send one typed manual intent to one coordinator with target key, current snapshot revision and expected before-version. The coordinator serialises its own attempts, rejects stale/double clicks, and publishes one shared attempt/progress/result projection. Review/open actions only navigate. A closed window never triggers another operation; reopening or a stale notification resolves to the current attempt. PAT-2670 owns menu lifecycle and notifications, including permission denial and deduplication. Managed counts remain separate from Patched actionable counts, Update all and scheduled eligibility.

Before dispatch, revalidate the accepted route manifest, current owning user/session, executable and source identities, prefix, receipt/bundle, version, pinned/skipped/deferred state, running guard, network mapping and supported external serialisation. Same-user executable/source mutation remains a trust boundary: a version string is insufficient. Reject wrappers, mutable/unverified code or changed evidence. Never switch accounts through privilege; if the current process cannot run as the verified owning user, hand off manually. Existing Core, helper and disposable-proof authorities stay unchanged.

Only a separately accepted native adapter may construct explicit executable URL plus argv from typed fields, never shell interpolation, login shells or user-supplied command strings. The candidate argv shape is `upgrade`, `--cask`, one validated official token; it is documentation, not an approved command. Any future additional no-quit/checksum/dependency options must be bound to the exact supported source. No broad operation, implicit token omission, tap, force, greedy, adoption, debug, ask or interactive option is allowed. Use no terminal/credential channel; do not pass askpass or answer prompts. Unexpected prompt/elevation evidence means attention, with stopping governed by the accepted safe protocol.

A child environment must preserve the verified account's required HOME, safe runtime resolution and explicitly mapped network choices while rejecting unassessed cask options, wrappers, executable overrides, Ruby injection and prompt hooks. Do not inherit the entire app environment or silently discard settings to obtain a pass. Child-only auto-update/cleanup controls need complete source-path proof; they do not change persistent Homebrew configuration. Source/runtime provisioning, migrations, new dependencies and unknown environment behaviour refuse before launch.

Proposed output ceiling is 64 KiB retained transient bytes across both streams and 256 bounded status records. Drain excess bytes in bounded chunks without retaining them; bound UTF-8 decoding, split lines and event allocations. Do not parse human progress text into completion or invent percentages. Translate only allowlisted observations into literal status/reason fields. Raw commands, environment, URLs with credentials, paths, tokens, terminal controls and secrets never enter Activity, diagnostics or Help. Retain only the operation correlation, route/version policy identifier, verified before/after versions, finite reason, outcome and evidence availability. Diagnostic opt-out applies to any future automatic reporting; Activity creates no send receipt.

Exit zero enters **Checking installed result**, not **Completed**. After observed child closure, independently reread the same canonical bundle and receipt; verify ownership, exact identity, expected developer/signature integrity, selected version/build/comparator, notarisation/Gatekeeper and compatibility under an accepted native verifier. Missing or changed evidence, unchanged version, different target or signer, foreign receipt, incomplete readback and unrelated mutations produce Needs attention or unknown outcome. Post-install checks cannot retroactively supply Patched's pre-install independent verification guarantee. Homebrew results must carry external-route provenance and no Patched transaction/recovery receipt.

Cancellation before dispatch abandons the intent with zero child calls. After dispatch, record **Stop requested** separately from stopped/cancelled. Permit cooperative cancellation only at a source-proven safe boundary with confirmed child/process-tree closure and readback. A timer, window close, app quit or output limit must not blindly SIGTERM/SIGKILL an install. Without such a protocol, disable mid-operation cancellation, disclose that limitation before starting, and retain an unresolved attempt if the app crashes or the child state becomes unknown. Do not retry while it may still be live. On relaunch reconcile ownership/process/evidence through an accepted adapter; if uncertain, show manual Homebrew recovery guidance without issuing repair/uninstall/cleanup commands or claiming an automatic rollback.
