## Evidence levels and future command references

**Source present** means inspected source exists. **Fixture defined** means the named checks are registered, not that this preparation ran or passed them. **Offscreen** means a check paints unshown content, not a person operating the application, chooser, permission dialog or assistive technology. **Native** means fresh observations on an approved disposable target. **Service** means actual authorised receipt/readback evidence, separate from fixture acknowledgements. Every missing/unavailable observation remains missing/unavailable; refusal is not successful completion of the requested update.

All commands below are existing reference commands for later authorised verification, from the repository root. `swift run --skip-build` requires a successful matching build first. `./scripts/verify.sh` runs `swift build`, registered Swift/Node source and fixture checks, and offscreen view checks. The separate Linux service gate is `./scripts/verify-service.sh`; neither command supplies actual service delivery proof. It neither launches the ordinary App product nor performs the complete native journey. Its inclusion here grants no runner/runtime authority. Proposed future integration checks must be prospectively accepted before execution; no missing command is invented here.
