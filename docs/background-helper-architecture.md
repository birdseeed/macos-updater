## Smallest privilege split

Recommend two optional embedded executables managed by `SMAppService`, rather than elevating the UI or restoring the old SaaS daemon:

1. **PatchedBackgroundAgent**, a LaunchAgent per consenting macOS user. It performs discovery, catalogue fetching/parsing, network/power/idle observation, downloads, notifications and policy evaluation without root. It uses only that user's login Keychain for their account session. It may invoke a separately authorised per-user transaction while that session exists. Register for each user through that user's app session.
2. **PatchedPrivilegedHelper**, an on-demand LaunchDaemon for protected/shared bundle replacement, machine activation-key operations and recovery. No general network client, shell, interpreter, downloaded script runner or URL opener. It parses only bounded protocol and trust envelopes needed to enforce its own action boundary. No discovery loop as root. It may consider already validated and securely staged login-window work when sessionless, under the restrictions below.

The daemon is needed for protected `/Applications` changes and machine-private identity; a LoginItem alone cannot supply system context before login. The agent is needed to keep sessions/downloads unprivileged. A third sessionless network broker is **not** recommended for launch: it would enlarge credential and transport scope before a requirement has operating proof. Consequently pre-login work after reboot can defer rather than fabricate a valid lease or run network code as root.

Proposed bundle layout: `Patched.app/Contents/Resources/PatchedBackgroundAgent`, `Contents/Resources/PatchedPrivilegedHelper`, `Contents/Library/LaunchAgents/im.patched.background-agent.plist`, `Contents/Library/LaunchDaemons/im.patched.privileged-helper.plist`. Plists use `BundleProgram`, relative to the enclosing bundle. Daemon Mach service: `im.patched.privileged-helper`; agent owns a session-local endpoint. Labels/identifiers are proposed, not current signed identities.

Use `SMAppService.daemon(plistName:)` and `.agent(plistName:)`, `register`, status and `unregister`, not legacy `SMJobBless`, copied global launchd files, login hooks or installer scripts. ServiceManagement status and IPC health are separate: enabled does not prove responsive/compatible. Check status at app launch and before new starts; explain notRegistered/requiresApproval/notFound/enabled-but-unreachable, with Open Login Items settings offered only on user action. Disabled status never triggers silent re-registration.

All app/helper binaries require verified Patched LTD Developer ID Application identity, hardened runtime, secure timestamp, notarisation and an authenticated initial app delivery path. Actual Team ID/designated requirements are PAT-7 facts to verify, never guessed. Recommend no App Sandbox for the direct installer product, no `get-task-allow`, no disabled library validation, JIT, accessibility, input monitoring or Full Disk Access requested by this design. Any necessary entitlement or new permission must be justified by a specific implemented route and approved separately. Root is not a substitute for TCC approval. Package/signing scope amendment belongs to a later implementation ticket.

## IPC and authority

Recommend low-level XPC with typed Swift wrappers and a small C shim, keeping kernel-delivered peer identity available. Before processing messages, set the peer code-signing requirement on both directions. Require the exact app/agent/helper signing identifier, Apple Developer ID chain and verified organisation Team ID, not any binary from the same team. Bind every operation to effective UID and audit session from OS peer metadata. Use `SecCodeCreateWithXPCMessage` for message-bound dynamic code validation where needed; never look up a reused PID or trust an `isAdmin`, bundle name, UID or path supplied in a payload. Verify SDK availability and identity forwarding/exec behaviour in the native proof. No private audit-token selector. Reject endpoint forwarding or changed message identity unless the complete peer check succeeds for that message.

Proposed protocol version 1, strict closed discriminated schema, 64 KiB control limit, 32 KiB signed catalogue record/lease sublimits, max 32 queued entries per UID and 128 per machine. Large artifact transfer uses a separately bounded descriptor stream; no XPC deserialisation of an executable object graph. Unknown version/type/field, invalid integer or duplicate key fails closed. Production catalogue owner must accept compatible bounds before code. No caller supplies a filesystem destination, executable, command arguments, installer URL, shell text or trusted verdict.

| Typed request | Exact authority and result |
| --- | --- |
| `hello(protocolVersion, clientBuild)` | Authenticated peer; returns helper build, accepted protocol range and capability/status enum, never credentials. |
| `registerTarget(catalogueAppID, scope)` | Helper resolves approved fixed application root, observes bundle ID/developer/volume/inode and ownership itself; returns opaque UID-bound target handle. `scope` is own-user or shared, never another home. No arbitrary discovery path. |
| `stageArtifact(targetHandle, candidateEnvelope, leaseEnvelope, artifactFD, byteLength)` | Snapshot bytes into helper-created private storage; digest/length, current catalogue signature/freshness and local native validation independently checked. Returns opaque stagedID. Passing this does not authorise installation. |
| `setPolicy(policyRevision, automaticEnabled, excludedAppIDs, pauseUntil, skippedReleaseIDs)` | Authenticated same-user policy update; durable monotonic revision, explicit UI provenance and helper setup required. Applies only to this principal's work. |
| `enqueue(stagedID, expectedInstalledIdentity, policyRevision, consentKind)` | Idempotent queue insertion, not transaction start. Manual/interactive/restart consent is exact app/version/digest-bound, not a general Boolean. |
| `start(queueID, attemptID)` | Rechecks all predicates below and starts at most once. Lost replies return existing transactionID/outcome under same attemptID, never another execution. |
| `status(queueID or transactionID)`, `cancelPending(queueID)` | Only owning principal; cancellation before start leaves old app unchanged. Active transactions report cannotCancelSafely where appropriate. |
| `recover(transactionID)` | Independently verified journal/physical state, no fresh licence requirement. No caller-supplied journal/path. Cross-user clients cannot read private status; helper may recover its own work without a session. |
| `prepareMaintenance()` | Block new starts, report durable quiescence generation only when all transactions/recovery are safe. Used by separately authenticated Patched self-update lifecycle; it grants no release/signing authority. |

Machine identity API is separate from installer IPC: `joinHousehold(verifiedMembership, challenge)` and `signDeviceChallenge(challengeEnvelope, purpose)` accept only service-authenticated account/purpose/nonces and exact bounded actions. No generic sign arbitrary bytes or export-private-key call. Licence owner must define signed household membership assertion/device-proof authorisation; an unsigned accountID or matching email is insufficient.

## Independent action-time checks

Only the helper can construct the nonserialisable `VerifiedInstallCapability` consumed by a proposed `InstalledTransaction.start`. A saved inspector report, UI enabled state, active licence, fixture candidate or catalogue route ID never constructs it. Under a per-target machine lock, immediately before mutation:

1. Revalidate peer/principal, enrolled target and current consent/policy revision; automatic work paused/excluded or any work with a recorded exact-release skip or revoked authority stays pending/refused. Manual work is unaffected by automatic pause/exclusions but cannot silently override an exact-release skip; explicit unskip is required.
2. Independently validate exact catalogue bytes with the app-embedded trusted public keys, signed artifact digest/length, identity, version, route, expiry/replay checkpoint and app compatibility. Unknown/retired key or expired record refuses. PAT-2606 owns the executable envelope/rotation contract; online catalogue signing authority cannot replace its own root. Licence trust, app release trust and catalogue trust stay separate.
3. Verify current entitlement against account/activation/key, monotonic sequence/revisions, terminal revocation and trustworthy time. Apply PAT-2605's accepted lease semantics; refresh occurs through the user's agent. No user refresh token in root storage. Missing/corrupt/reboot-invalid time means no new start. Recovery is outside this gate.
4. Copy from an untrusted descriptor only into root-owned 0700 staging, files 0600, single-link regular artifact, immutable verified byte snapshot. Validate actual Developer ID/signature, expected vendor identity, notarisation and installed bundle metadata on that snapshot, then revalidate staged bytes before exchange. DMG/container and contained-app results remain distinct. Handle executable modes and legitimate bundle links in a separately proven production tree reader, never by relaxing fixture guards globally.
5. Resolve destination through held nonfollowing directory descriptors under approved `/Applications` or the principal's own approved `~/Applications`. Shared destination ancestors and mutation-sensitive parents must be root-controlled, with no untrusted write/ACL route; otherwise protected replacement is unavailable. Verify ownership, permissions, same-volume atomic primitive, target device/inode, developer/bundle/version and free space for both bundles plus staging. Never chown unrelated paths to force eligibility or follow aliases, translocation, external-volume substitutions, symlinks or hardlinks into arbitrary destinations.
6. Check all users/processes using the target and helper executables, including background components and vendor updater activity, using route-specific identity evidence. Agent NSWorkspace observations alone see insufficient global state. Missing process-inspection permission or uncertain updater coordination defers. Recheck immediately before exchange and verify observed target again afterwards. A private Patched lock does not lock a vendor updater.
7. Recheck power, awake/idle (automatic only), installer interaction/restart requirements and session/launch transitions. No stable safe route evidence means Needs your attention or deferred, never optimistic execution.

The descriptor approach narrows TOCTOU but cannot make an adversarial app launch impossible. An atomic bundle swap is not proof that launch/installer races are harmless. Each route must prove that a launch immediately before/during exchange cannot run a partially installed tree or break recovery; otherwise it is excluded from unattended execution. Never block login or install an app-launch interceptor to hide this limitation. If a target or vendor updater changes unexpectedly, do not overwrite it with stale before-image data: stop, preserve evidence and require attention.

## Queue, schedule and exact proposed defaults

Persistent policy/app exclusions use catalogue stable app identity plus vendor signing identity, installation scope and helper-enrolled target identity. A display name or changing path is not the exclusion key. Catalogue identity migration requires explicit mapping review; unknown identities inherit no automatic permission. Persist settings across launches/restarts and never re-enable opt-out after upgrade.

Recommend one daily discovery deadline per user, based on last successful check plus 24 hours, with persisted random jitter up to 30 minutes. First check on first active session; coalesce missed days into one check on next awake opportunity, never a catch-up burst. Customer can Check now, pause automatic third-party installs until a chosen resume time, toggle automatic updates, exclude individual apps, skip exact releases and disable background service. Pause is not a blanket background/download/notification stop. Persist an absolute UTC resume deadline with original timezone/display intent; check across sleep/restart, re-evaluate on wake and require fresh time evidence after clock uncertainty rather than early resume. Timezone changes alter display, not the selected instant. These time mechanics are engineering proposals, not owner-selected presets. At resume recheck opt-in, exclusions/skips, entitlement, fresh catalogue/artifact, installed identity, sessions/processes, permissions and power/network. Notification: coalesce each automatic run's completed outcomes into one summary, separately preserve actionable attention transitions; the proposed daily check aggregate does not suppress safety/permission/recovery status or introduce an additional owner-selected notification frequency. Deduplicate by principal/run/transaction/exact release/outcome and attention-state revision, with per-app status in app. If notification permission is denied, keep the badge/status and next-open summary. A notification never starts an install.

Recommend idle >=10 minutes from `CGEventSourceSecondsSinceLastEventType` as an agent signal, combined with session/process evidence. No captured input or accessibility permission. Recheck at start and before exchange; unknown idle is ineligible. Re-evaluate on wake, logout/login, target exit, policy/network/power changes; add 2-minute debounce and retries at 5, 15, 60 minutes, then next daily opportunity. At most three transient automatic attempts per app/day. Trust refusal is not a blind retry. Losing idle before mutation defers; after mutation use safe transaction/recovery, never arbitrary cancellation. Do not request wake timers or assertions to create an update opportunity.

Root state proposed under `/Library/Application Support/Patched/Helper/`, root-owned 0700, queue/journals/checkpoints 0600 and no user-writable ancestor. Per-user data stays in `~/Library/Application Support/Patched/`, owned 0700. Store schema version, queueID, dedup key `(principal, target identity, exact candidate digest)`, account/activation references, request/attempt IDs, policy revision, consent binding/deadline, candidate/lease exact bytes, staging digest, expected installed identity, retry timestamp and state. No email, consumer token, arbitrary URL or user-entered name in helper log. Persist via exclusive temporary file, fsync/full-sync, atomic rename and directory sync; never claim crash/power-loss resilience until tested.

State machine: `discovered -> waitingDownload -> staged -> queued -> deferred/needsAttention -> starting -> installing -> committed` or `recovering -> safelyRestored/unsafeAttention`. Dedup survives lost replies/reboot; leases and consent are re-evaluated, not frozen permission. Only one transaction per physical destination across UIDs/accounts and one global unsafe-recovery barrier. Multi-app batch is serial initially to reduce shared hazards. A failed attempt permits continuation only with verified old identity/complete tree, durable rolledBack journal, no vendor/process conflict and released transaction lock. Shared storage corruption, unknown target, unavailable trust/time or uncertain recovery stops batch. Report each succeeded/failed/deferred/needsAttention result separately.

Proposed retention: discard unstarted staging after 7 days or immediately on obsolete candidate/revocation; keep the logical queue with Needs fresh check. Cap staged bytes at 5 GiB machine-wide and one artifact per target; when full defer rather than delete active recovery material. Retain completed minimal history 30 days. Never purge an unresolved journal, before-image, revocation/replay floor or state needed by a still-valid lease to meet a quota. Cleanup requires a separately tested policy. No cleanup runs in this task.

## Login window and session transitions

Login window is the OS session opportunity after logout/before a desktop session, not screen lock, Fast User Switching or FileVault preboot. The daemon cannot run before FileVault unlock makes its app/data available. Do not infer sessionlessness from a visible login screen, `CGSessionCopyCurrentDictionary` for one caller, or absence of the console user alone; prove all relevant sessions/processes quiescent with supported native observations. Missing/uncertain evidence defers.

For launch recommend sessionless execution only of pre-staged, fully unattended routes with a still-valid same-boot lease, valid stored opt-in, current exclusions and native trust recheck. No locked login-Keychain access is assumed. Work survives reboot, but **new pre-login starts after reboot defer until an authenticated session refresh re-anchors entitlement time** under the current licence clock proposal. Offline same-boot logout can use the existing bounded lease; revoked/expired/stale work cannot start. This is an explicit availability limitation, not a promise of pre-login completion. PAT-2605 must accept the interface; enabling sessionless refresh later would need a narrowly scoped machine credential and unprivileged transport design, not copied consumer tokens.

Observe session transition generation while preparing; login/app launch before mutation invalidates the opportunity and leaves queued work. If login starts after the route's irreversible point, let sign-in proceed immediately and complete/recover under the route's proven safety contract. No loginwindow plug-in, login hook, desktop hold, forced logout, process termination or surprise installer UI. Routes that require blocking access to finish, cannot safely coexist with launch or cannot defer their restart are ineligible. Automatic login may provide no opportunity at all. Fast User Switching can leave another user's apps running; the shared target remains deferred.

## Network, power and attention controls

Limited means `NWPath.isConstrained || isExpensive`; these are OS cost/Low Data Mode hints, not universal metered billing detection. Recommend unknown signal defer automatic installer download, while checks stay bounded. Limit each discovery cycle to 1 MiB metadata total, per request 256 KiB, two redirects within approved HTTPS origins, 30-second timeout; refuse oversize, retain last-known state labelled stale. Catalogue owner must reconcile those preliminary byte budgets with the shared full-catalogue/projection limits; fetch global revisions or signed manifest chunks, never installed-app-specific records. Do not silently truncate or leak local inventory. Licence refresh keeps its independent smaller limits.

Use `URLSessionConfiguration.allowsConstrainedNetworkAccess = false` and `allowsExpensiveNetworkAccess = false` for automatic installer sessions, with bounded `waitsForConnectivity`, as well as path monitoring to narrow path-switch races. Small capped checks and explicitly overridden transfers use separate sessions; no automatic install permission comes from those transport flags. On a restricted transition, suspend automatic transfer at a safe chunk, retain private partial data for 24 hours and resume only with matching strong validator/digest/expected total length; otherwise restart. Verify full final bytes regardless of resume. Download anyway applies to the chosen app/version/digest for that transfer (24-hour maximum), ends at completion/cancel/changed candidate and never persists as a global override. It does not override OS-enforced restrictions, entitlement, exclusions or install timing.

Recommend low battery enter at <=20%, resume >=25% for hysteresis; Low Power Mode pauses new automatic installs regardless of charge. Use ProcessInfo power notifications and IOKit providing source/current/max capacity. Desktop with verified unlimited power is eligible without a battery reading; missing battery/power signal on a portable means defer automatic start. Recheck before start; manual route can warn and proceed only where per-route minimum energy/time prerequisites are proven. Mid-install power/Low Power change never causes abrupt termination; complete or recover safely. Small checks remain available; downloading is separate and may use discretionary power-aware scheduling. No change to system power settings.

Restart-required and interactive work remains durable Needs your attention. Proposed manual consent identifies exact app/from/to/digest, requirement and consequences, lasts 30 minutes, expires on logout, cancellation, candidate/target/route change or policy invalidation. Restart approval is pre-start and separate from choosing restart later. It never authorises an immediate OS restart. Unknown or unexpectedly discovered restart/interaction requirement stops before mutation where possible; after mutation follow the proven no-forced-restart recovery path. A route unable to suppress a forced restart is unsupported. On explicit Proceed, launch only the verified allowlisted installer in the requesting user's session; record cancelled/succeeded/failed/unknown return and independently read back actual result. No universal vendor automation promise.

## Shared Mac, removal and self-update

Propose one random machine identity, with a separate activation binding/key per household account, inside helper-protected machine storage. Same-household signed-in local users join the same activation through service-authenticated membership proof; distinct households never merge. Device key is hardware-backed where available, secure device-only nonsynchronising software fallback otherwise, with explicit weaker assurance/cloning limit. Actual system Keychain ACL/availability/access group and reinstall behaviour require proof. Root retains key reference; it returns purpose-bound signatures, never private key or another user's token. Each user retains separate account session and consent, root scopes status/access to authenticated membership. Unknown household membership cannot join merely by being a local admin or sharing a Mac name. Administration of the Mac cannot be claimed as protection against a determined administrator.

Conflicting shared-app policies: one enrolled machine-wide shared-target policy is set through explicit administrator-approved setup, identifying the participating household and installation scope. A newly joining user never silently overrides it. On conflicting/unknown household or active-user exclusion, defer shared automatic work and explain conflict; manual shared change requires explicit scope confirmation and all-user safety checks. No session grants another user's home access. Removing a user drops their policy/session association and cancels unstarted user work; shared activation remains while other authorised members use it. Remote deactivation records a terminal marker, releases slot at service, and prevents all corresponding new starts at next verified refresh; in-flight recovery continues.

If helper is declined, discovery/manual unprivileged capabilities remain where separately implemented. Protected updates, sessionless queue execution and secure machine-wide joining are unavailable; do not silently allocate an extra slot per macOS user. Explain that shared-Mac activation needs the optional component or an accepted alternative. Per-user Firefox proof is unchanged. If only the agent is disabled, checks while UI is open remain possible; no promise of closed-window checks. Closing window leaves approved agent work active. Quit Patched closes UI; offer separate Pause background updates/Disable background service with explicit effect. Pause automatic updates prevents new automatic third-party installation starts, including login-window starts, not manual starts, routine read-only checks or recovery. Download/background-service disable controls have separately explained scope; neither changes Patched self-update or vendor settings.

Disable/remove: first persist no-new-starts and request maintenance quiescence. Unregister agent for that user; administrator-scoped daemon removal waits for safe completion/recovery. If OS externally revokes/kills helper mid-transaction, do not claim cleanup succeeded; retain protected journal/old bytes and show recovery required at next approved enablement. No silent OS reapproval. Unregister success does not prove data or activation deletion. Recommend retain machine activation identity across app uninstall/reinstall until explicit household deactivation, so reinstall can reuse slot; disclose retained identity and offer separately confirmed removal after deactivation and safe recovery. Removal must not delete unresolved recovery evidence. Actual uninstall/reapproval behaviour is a target proof gate.

PAT-2609 owns Sparkle integration and release keys. Use maintenance generation handshake: suspend new third-party starts, drain/verify durable queue and active recovery, stage signed compatible app/helper, install/relaunch only at safe opportunity with unsaved UI state preserved. Resume only after matching supported protocol/schema versions and helper identity handshake. Protocol/schema migration must be reversible or preserve old reader until upgrade success; incompatible helper returns Needs app update, never fallback to unauthenticated IPC. Helper permission changes need customer approval/reapproval. Patched self-update opt-out persists separately from third-party opt-in. Trial/paid expiry does not block legitimate Patched self-update; normal network/power/trust/quiescence rules still apply. Helper registration never grants self-update release authority. Failed update keeps compatible previous app/helper and queue; no mixed-version new starts until recovery/compatibility is proven.

## Optional reporting boundaries

PAT-2608 accepts a prominent setup offer for general crash/error reporting only after affirmative consent, plus a separate feature-usage analytics opt-in. The 12 October narrow override makes automatic failed-update reports default ON with visible opt-out; see [PAT-2665](automatic-failure-report-integration-brief.md). User-submitted manual support includes previewed diagnostics by default with opt-out, but always requires explicit submission; see [PAT-2664](manual-support-form-integration-brief.md). Coverage sharing remains separate opt-in. The general opt-in rules here cannot override those two bounded flows; current ordinary UI has no reporting or support send. Neither may gate functionality/entitlement or imply consent to the other. Explain/preview report categories and actual app-specific fields before consent; detailed support bundles still need exact preview/submission. Analytics is limited to Patched feature use, excludes installed-app names/personal content, and neither channel may encode inventory, arbitrary text/output, personal paths, tokens/codes/payment claims or secrets. Per-user versioned consent and later independent off switches must prevent future sends, including unsent buffers; check consent at dispatch and after asynchronous work. Keep redaction/schema validation before private bounded buffering. No provider or destination is operationally selected and no pipeline is implemented. H9 and the final reporting amendment below propose schema/buffer/retention mechanics, requiring acceptance before telemetry implementation/credentials; do not add telemetry to helper IPC, inventory requests or current gates by inference.
