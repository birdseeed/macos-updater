# PAT-2580 Firefox artifact inspection contract

This bounded proof inspects only the exact official universal Firefox 157.0 and 157.0.1 DMGs pinned in `firefox-artifact-evidence.json`. Andy approved the current Mac for download and read-only inspection. No installation, application launch, profile change, target replacement, helper, root service, scheduling, credentials or production release is authorised. The source recipe remains historical and non-actionable.

## Acceptance-first evidence

The parent independently ran the first-phase dependency-free Swift API stubs and executable harness: the package built, then all 161 checks failed behaviourally with `notImplemented`. The parent authorised implementation only after observing that result. The original 161 cases remain unchanged; eighteen additional cases strengthen duplicate JSON key rejection, strict UTF-8 encoding and full-document parsing, descendant-process timeout handling and isolated spawn-failure refusal. The encoding regression was demonstrated with eight behavioural failures before its fix; BOM and non-UTF-8 trust records are refused. `./scripts/verify.sh` retains the original reference checks and then runs `./scripts/verify-artifacts.sh`.

The harness uses synthetic command output explicitly labelled fixture, physical private temporary directories, and harmless local subprocesses only. It does not download or mount a DMG. All negative assertions require a named refusal, not any thrown exception. Positive assertions prevent an always-refuse implementation from passing.

## Operator interface

- `artifact-inspector verify-record <record.json>` checks the bounded record against compiled exact pins. It reports consistency with reviewed repository pins, not fresh OS validation or independently authenticated vendor bytes.
- `artifact-inspector inspect-local <157.0|157.0.1> <absolute-dmg-path>` verifies exact local bytes and performs fresh macOS read-only inspection.
- `artifact-inspector download-inspect <157.0|157.0.1>` obtains the exact official artifact into a newly created private workspace, then performs the same checks.
- `artifact-inspector replay <157.0|157.0.1> <evidence.json>` re-evaluates recorded raw observations as cached evidence. Replaying cannot grant fresh OS validation or installation authority.

The replay command takes the `evidence` object from a report, not the enclosing report or its asserted assessment. Commands produce bounded JSON evidence on stdout and an actionable refusal reason on failure, with nonzero exit. The program will never turn an arbitrary URL, script, version, manifest flag or target path into installation authority. Pinned input selection is compiled; changing a record and a file together cannot create a new approved target. Parent acceptance includes both exact existing DMGs and tampered bytes.

## Network and local-file boundaries

Only HTTPS host `archive.mozilla.org` is reviewed. The initial URL must match the exact encoded pinned URL. Every redirect is validated before following it; no implicit host expansion, HTTP downgrade, userinfo, port, query, fragment, control character, path traversal, double encoding, encoded separator or ambiguous spelling is accepted. Limits are three redirects, 180 seconds, 170,000,000 bytes and the stricter exact artifact byte length. A validated chain still needs the exact SHA-256 and length before any image tool runs. A matching hash binds bytes to a reviewed pin; it does not independently authenticate Mozilla.

Open local paths component-by-component without following symlinks, including ancestors, and hash from the open regular-file descriptor with bounded streaming reads. Reject relative paths, traversal, non-regular files, missing input, byte-length and digest mismatches. Production must not resolve away supplied symlinks. The tests resolve Foundation's platform `/var` alias only when creating their physical baseline fixtures. Inspection copies local input or receives downloads inside an exclusively created user-owned mode-0700 workspace. It opens the completed stage read-only through the held directory with no symlink following, compares its device/inode to the writer, syncs and sets mode 0400, closes the writer, unlinks the staged name, and hashes the retained reader. The same verified object stays alive through image verification, read-only attach, payload and container checks, and detach. Descriptor-based verification and container commands rewind the retained reader and explicitly inherit it through child slot 198 using posix_spawn dup2; their actual operand and recorded schema-3 dmgPath remain /dev/fd/198. Attachment alone uses the private bounded byte bridge described below, tied to that same object. Parent descriptors keep CLOEXEC. Darwin POSIX_SPAWN_CLOEXEC_DEFAULT excludes every unrelated inherited descriptor, including parent descriptors without CLOEXEC; explicit actions retain only standard streams and image slot 198. No writes occur to the supplied DMG or existing apps.

This binds pathname replacement to the retained object, including replacement of the former stage name or its ancestors. Mode 0700, chmod 0400 and an unlinked name do not provide an immutable seal against a hostile same-UID process with an already-held writable alias, or one able to interfere with this process. In-place mutation remains a limitation; descriptor identity and length checks do not prove immutable content. Borrowed descriptors in the Testing SPI expose that limitation and never create fresh OS or installation authority.

PAT-2710's inert child checks exercise the ordinary factories and bounded spawn transport without calling hdiutil or mounting. Both native descriptor attachment hypotheses failed with Bad File Descriptor after successful image verification: the default helper route and the subsequent `-kernel` route. Both failures and their successful cleanup remain recorded; neither establishes a mounted inspection.

The next candidate serves the already verified, unlinked read-only reader through one temporary in-process HTTP byte bridge. It binds only numeric 127.0.0.1 on an exclusively owned ephemeral port, with a fresh 256-bit random token path. It has no outbound connection, name lookup, proxy, upload, arbitrary-file or redirect route. A duplicate of the exact held descriptor supplies bounded pread chunks without changing the shared offset; device, inode, size and read-only status are validated before and after every read. Its lifetime includes payload inspection and owned detach. Stop interrupts socket waits and requires the single worker to join and close its reader, listener and accepted client within two seconds; a timeout or cleanup failure preserves the outer workspace.

The protocol permits only GET/HEAD with the exact numeric Host and token path, fixed identity response framing, and one valid closed, open or suffix byte range. It refuses malformed, duplicate, folded, body-bearing, framing or oversized requests without image bytes. Hard limits are 8192 header bytes, 65536 bytes per body chunk, 8192 accepted connections including malformed requests, eight image lengths of actually sent body bytes, a 180-second global lifetime, a two-second header deadline and a 30-second connection deadline. A prospective response exceeding the remaining byte allowance is refused before any body. Test limits can only lower these caps. This loopback OS read is separate from vendor acquisition: it changes neither sourceURL/redirectChain nor transportObservedThisRun. In-place writable-alias mutation remains a limitation; metadata checks are not an immutable content seal.

Actual hdiutil compatibility with this bridge and mounted-object binding on the intended macOS release remain unproven. There is one productive attachment route, with no descriptor, kernel or staging-path retry after failure. Synthetic transport and pure command-policy checks do not prove a genuine mounted inspection, installed update or customer readiness.

## Read-only mount and process boundaries

Run fixed system binaries with argument arrays, no shell interpolation. Capture actual exit status, separate stdout/stderr, start/finish times, timeout and output-limit conditions. Bound each command to 30 seconds and combined captured output to 1 MiB; an explicit longer bounded allowance for image verification may be introduced with a test if measured need warrants it. Nonzero exits, unavailable tools, timeouts and truncation cannot become passing app evidence. Operator subprocess output is data, never instructions.

Verify the image, then create one bridge and attach with exactly `hdiutil attach -readonly -nobrowse -plist -mountpoint <exclusive-owned-child> http://127.0.0.1:<owned-port>/<token>/artifact.dmg`. The typed command route requires literal /usr/bin/hdiutil, that exact command order, the active source owned by the identical VerifiedImage object and a safe absolute mount path shorter than `MAXPATHLEN` bytes. A raw URL or command-shape boolean cannot supply this capability. Actual attach URL arguments are recorded in the ordinary command results; report/evidence schemas and descriptor-based container observations stay unchanged. The legacy public pathname-only fixture API retains its original command shape. The earlier pure kernel-command fixture policy remains historical shape coverage only. This internal OS image-reader route grants no application or installer launch, helper installation or installation authority. Parse the attachment plist and require exactly one mounted payload at the owned path; unrelated mounts are neither inspected nor detached. Detach only that exact owned path on normal completion and payload failure. Attachment failure may leave a mount: reconcile the exclusively owned mount path and clean it if present without trusting an arbitrary tool-returned device or foreign path. Detachment failure is reported as `cleanupFailed`, preserving the workspace/evidence for owner recovery rather than deleting a mounted tree. Do not recursively remove any unverified or mounted path.

## Payload assessment and recorded evidence

Read the actual app plist and executable from the owned read-only mount. Require bundle `org.mozilla.firefox`, the exact selected numeric dotted version, package type `APPL`, safe executable `firefox`, and exactly arm64 plus x86_64. Refuse symlinked payload roots/metadata/executable and unexpected or ambiguous application payloads. Require `codesign --verify --deep --strict`, exact signing identifier and Team ID `43AQ936H96`, app `spctl --assess --type execute --verbose=4` exit zero with accepted `Notarized Developer ID` output for the same app, and a successful app `stapler validate` result. Contradictory output, wrong invocation or wrong target is refusal even when an asserted success flag or exit zero is present.

Record image verification and the DMG signature, open-assessment and stapler observations separately from app checks. Both previously inspected DMGs were unsigned: container exits were 1, 3 and 65 respectively. A valid app assessment does not rewrite those results into a blanket container pass. The original `report.json` with overall `inspection_pass: false` and its parent adjudication remain unmodified. The new pinned record links those dated observations and explicitly preserves their limitations.

Record exact source and redirect chain, byte count, digest, selected identity, observed timestamp, OS version/build, command arguments, actual exits and bounded output. Fixtures and loaded records cannot assert fresh OS validation. A replay is only a consistency evaluation of untrusted supplied observations; anyone can fabricate a record. Returned assessments are immutable and output-only. Serialized assessments are untrusted text, never a downstream authentication mechanism; replay re-evaluates raw observations and rejects supplied trust flags. No public setter or success boolean in a record grants live trust. Official checksum-list matches are corroboration only; GPG verification has not been performed or claimed.
