## Proposed coordinator contract

One future owner serialises inventory generations, accepted preference revisions, queue transitions and verified transaction outcomes. Both screens observe its immutable projection; commands carry the selected application instance, release and observed generation. A stale UI command requests fresh evaluation rather than reusing an earlier eligible result.

The proposed internal boundary has four operations: refresh a read-only inventory snapshot, project current state, request a manual or bulk start, and reconcile an existing attempt. These are conceptual interfaces pending parent architecture acceptance, not a new public API or permission grant. Scheduled requests later enter the same start path only through their separately accepted operating adapter.

Bind product, bundle, publisher, channel, edition, architecture, application instance and location, installed version/build, candidate release/build and artifact digest, catalogue identity/sequence/freshness, principal and preference revision. Do not guess across duplicate app copies or ambiguous editions. The existing release model includes product/scope/release/build/edition/channel/artifact (`Sources/PatchedScheduling/SchedulePolicy.swift:8`); native instance, publisher and architecture binding must be proved by the future adapter, not invented from its display name.

Immediately before each start, independently revalidate the exact target and source, current running state, permissions and route, catalogue freshness/replay state, artifact bytes and fresh native checks, current policy and accepted mutation authority. A queue attempt is a correlation handle, never that authority. Preserve the existing transaction engine and refusing ordinary entry points until a real bound native authority and target scope are separately accepted. Do not add a second transaction engine or a `ClientController.perform` bypass.

Keep manual and bulk requests in one shared serial queue. Defer running apps without forced quit. New automatic starts require opt-in, current exclusion and pause checks, known eligibility, closed target, awake/idle observations and an allowed route (`Sources/PatchedScheduling/SchedulePolicy.swift:100`). An exclusion stays visible and does not suppress manual or Update all eligibility. An exact-version skip blocks manual, bulk and unstarted automatic work until explicitly undone; a proven later release can be considered afresh.

Only fresh matching physical completion/readback can publish installed success. Child exit zero, installer return, stdout, a saved report or an optimistic UI transition cannot do so (`docs/client-installed-flow.md:82`). Cancellation invalidates stale display responses while retaining ownership of any executing transaction and its recovery (`:74`). Retry creates a fresh correlated attempt without overwriting the previous failure or original version.

Continue independent eligible work only after restoration and failure isolation are proved. Uncertain recovery or shared checks stop unsafe new starts; policy changes cannot interrupt required completion/recovery. Preserve the queue barrier and its refusal to clear a shared fault through an isolated rollback claim (`Sources/PatchedScheduling/QueueModel.swift:117`, `:124`, `:132`).
