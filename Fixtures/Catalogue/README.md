# Deterministic catalogue fixture contract

This fixture set exercises the native catalogue verifier, artifact consistency check and explicit fixture state bootstrap.

## Signed bytes and schema

The envelope is a strict UTF-8 JSON object with exactly `keyID`, `payload` (base64) and `signature` (base64, 64-byte Ed25519). Its maximum size is 128 KiB. Reject BOMs, other encodings, malformed JSON, duplicate decoded keys (including escaped spellings), non-whitespace trailing bytes and unknown fields. The payload has a 64-KiB maximum and maximum nesting depth 16. It is verified over its original bytes, never reserialised for signature verification or hashing.

The exact Ed25519 message is the UTF-8 bytes of `im.patched.catalogue.v1`, one NUL byte, then the exact decoded payload bytes. The signing key is supplied explicitly as a `FixtureTrust` public key. Envelope and signed `keyID` must equal the configured key. Signed `catalogueID` must equal the configured catalogue. No key discovery, production trust store or embedded private key exists in the core. Deterministic private keys are generated exclusively in the `Tests/PatchedCoreChecks` and `Tests/PatchedCoreRegressionChecks` targets from unmistakable fixture bytes.

Payload schema 1 has exactly these fields:

- `schemaVersion`: integer 1; `domain`: `im.patched.catalogue.v1`; `keyID`; `catalogueID`.
- `sequence`: positive UInt64 integer, never boolean, floating point or coerced string.
- `issuedAt`, `expiresAt`: Unix seconds in the supported range 0 through 9,007,199,254,740,991 (2^53 minus 1), integer tokens. The caller clock must be finite and in that same range, so signed integer seconds remain exactly representable when compared with its Double value. Expiry must exceed issue time, with a lifetime at most 259,200 seconds. Issue time may be at most 300 seconds ahead of the finite nonnegative caller clock. Expiry is exclusive: equality with the current time is expired.
- `artifact`: exactly `bundleID`, `teamID`, `platform`, `minimumOS`, `maximumOS`, `version`, `sha256`, `byteLength`.

The artifact requires the caller's exact bundle/team identity and macOS platform, an inclusive OS range, and a version strictly newer than the installed version. Numeric dotted versions contain one to eight unsigned decimal components, each at most UInt32.max, without leading zeroes except `0`. Comparison pads absent trailing components with zero. Invalid syntax, reversed OS ranges, malformed caller versions and absent constraints fail closed. The digest is exactly 64 lowercase hexadecimal characters; byte length is a positive integer at most 170,000,000. Unexpected script, URL or authority fields are rejected.

A `CatalogueCandidate` is immutable output with no public constructor or decoder. It always says `origin: fixture`, `freshOSValidation: false`, `installationAuthorized: false`. `ArtifactVerifier.verify` checks bytes through a bounded no-follow descriptor read. `approvedInspectionTarget` returns an existing compiled Firefox pin only after matching the exact identity, version, digest and byte length; it does not run an inspector or issue a passing assessment. Existing PAT-2580 output-only assessments remain unchanged.

## Physical fixture state

The caller provides an absolute physical path to a named owned proof namespace. `bootstrapFreshProofNamespace` is the explicit authorisation to create that fresh namespace. It first validates the input, exclusively creates the namespace, and refuses every existing namespace, including empty or corrupt ones. Ordinary `verify` refuses missing directories, marker, checkpoint or lock files. Neither operation silently resets or heals state.

Namespace mode is 0700, owned by the effective user. Every state file is a regular, single-link, owned mode-0600 file. Paths are walked with descriptors and no-follow/nonblocking opens, including all ancestors. Symlinks, FIFO/device/directory substitutions, hardlinked state, traversal, relative paths and unsafe modes are refusals. `lock` is an exclusively created persistent file; descriptor-held exclusive nonblocking locking serialises writers without deleting or replacing the lock inode. Path identity is rechecked across commits; a replaced namespace is uncertain state and fails closed.

Bootstrap holds descriptors for every ancestor from the root to the parent, creates the namespace with `mkdirat` on the held parent, and opens the new directory through that same held parent without following symlinks. It never walks the path again from the root. Before `lock` is created, again before `namespace.json` is created, and at each confirmation during durable acceptance, every held ancestor and the held namespace must still be the directory named at its original position. A renamed or replaced ancestor refuses with `unsafePath`, no file is written into the replacement, and the original incomplete namespace is preserved for inspection rather than removed or reused. This guarantee has a limit: `mkdirat` returns no descriptor, so a same-user process that swaps the new child inside the held parent before its first open is not detected by identity. The owner, mode and exclusive-create checks still apply to whatever directory is opened. The test-only bootstrap boundary runs after the real `mkdirat`; it can observe or refuse and cannot return an accepted result.

`namespace.json` is a strict object with `schemaVersion: 1`, `namespace: patched-fixture-state-v1`, `keyID` and `catalogueID`. `checkpoint.json` is a strict object with `schemaVersion: 1`, `keyID`, `catalogueID`, positive `sequence` and `payloadSHA256`. Both are bounded to 8 KiB and use the same strict encoding/duplicate-key rules. Highest sequence and SHA-256 cover the exact signed payload bytes. A lower sequence fails; an equal sequence succeeds only for an identical byte hash. Reformatting the same JSON object creates a different payload and is refused at the same sequence.

Persist before returning any accepted candidate. Write an exclusive temporary file in the owned directory, call `fsync` and `F_FULLFSYNC` on that regular file, atomically rename onto the checkpoint, call directory `fsync`, then `F_FULLFSYNC` on the committed regular checkpoint again. Every failed syscall refuses acceptance; unsupported full flush has no weaker fallback. Bootstrap also synchronises namespace creation through its parent. Re-read and validate physical state while holding the lock. Never accept on partial write, failed sync, failed rename, lock conflict or uncertain path identity. A failed write may leave a private temporary checkpoint for evidence; it never grants acceptance. Recovery must read a complete old or new checkpoint. The test-only persistence probe throws at real write/sync/rename boundaries and cannot bypass persistence or construct an accepted result. Separate sync probes inject refusal before each of the four required checkpoint sync operations. The final acceptance path checks physical checkpoint identity and contents after both flush requests. macOS `fsync` alone does not flush a drive's volatile cache; Apple describes the stronger request in its [fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html). Successful syscalls and restart tests do not prove survival of every hardware failure. No physical power-loss test or universal storage guarantee is claimed.

The persistence assumption is a trusted same-user namespace. Without an external monotonic anchor, restoring an earlier complete valid checkpoint cannot be distinguished from genuine older state. This proof does not claim cryptographic resistance to same-user backup restoration, or detection of an entirely deleted historical namespace when the caller explicitly authorises a fresh bootstrap. Missing or malformed state always fails ordinary verification.

## Acceptance and operating limits

`./scripts/verify-core.sh` builds and runs the dependency-free native executables: 236 original cases and thirteen added regressions. The latter first demonstrated four clock failures (including improper acceptance of a proof issued 400 seconds ahead at a 2^62 caller clock), then five missing-flush failures, then improper bootstrap acceptance inside a replacement parent directory, before their respective repairs. A normal bootstrap control accompanies the ancestor-replacement case. It checks both acceptance and exact named refusals, physical checkpoint bytes and modes, reconstructed-verifier replay, a separate process restart, process lock contention, and injected commit failures. It uses only disposable physical fixtures beneath the worktree's `.build` directory. A child probe has an eight-second bound; it neither launches Firefox nor performs network or installation actions.

The full `./scripts/verify.sh` retains all twelve reference checks, all 179 artifact checks and actual provenance/pin verification, then adds these core cases. It replaces the old XCTest prerequisite on this Command Line Tools-only Mac without weakening behavioural acceptance. Independent parent acceptance and full-diff OpenCode/NVIDIA review remain required before publication. No Windows parity, release, installed transaction, helper or scheduler is implied.

## Fixture-only consumer command

`patched-core-proof` consumes a supplied public fixture key and signed fixture bytes. It never signs, creates keys, publishes, downloads, invokes OS inspection, installs or launches an app. The fixed caller identity is Firefox's bundle and Team ID; matching bytes or a catalogue signature remains only fixture consistency.

After `swift build`, use:

```sh
swift run --skip-build patched-core-proof verify-fixture /absolute/catalogue.fixture.json /absolute/public-key.fixture.raw fixture-only-ed25519-v1 fixture.firefox /absolute/owned/state 1800000000 27.0.1 157.0
```

Use `bootstrap-fixture` in place of `verify-fixture` only to explicitly create a fresh namespace. Use `verify-artifact-fixture` with a final absolute artifact argument to check its digest and length against the validated candidate. Ordinary verification refuses absent, corrupt or reset state; an existing namespace is never repaired by bootstrap. Public-key and envelope inputs are bounded regular files opened without following symlinks in any component. Output is JSON with explicit fixture and no-OS/no-install fields. Refusals exit 1; usage errors exit 2.

The **test target only** can emit its own fixed fixture using `patched-core-regression-checks --emit-fixed-fixture /new/absolute/directory`. This exports a public fixture key, two fixed signed catalogues, their fixed bytes and a tampered sample; it exports no private key and cannot sign supplied content. `--prove-persistence-boundaries /new/absolute/directory` records nine injected-failure runs, preserving each physical old-or-new checkpoint and temporary evidence for inspection. It labels these results fixture and explicitly records that hardware power loss was not tested. These developer proof utilities do not implement an operator signing or publishing workflow.
