# Licensing L1 fixture vectors

These exact UTF-8 JSON envelopes are deterministic, test-only signed lease inputs. Their fixed RFC8032 signatures were independently prepared using existing Node v26.10.0 built-in crypto, with no installed dependency. The exact domain-plus-payload to signature corpus is embedded in the Swift check target; unknown input refuses. This is a fixed fixture assembler, not a general deterministic Swift signer. The private fixture seeds exist only in `Tests/PatchedLicensingChecks/Fixtures.swift`; they are public test data, never production signing material. The library has no default trusted key. Check signatures use `im.patched.licence.v1`, a NUL byte and exact payload bytes. Schema/member ordering follows licensing-contract section 4. The check executable compares every vector byte-for-byte with its Swift fixture assembler and independently verifies every corpus signature using CryptoKit, including the explicit catalogue domain on the wrong-domain vector. Apple CryptoKit signature generation is intentionally randomised; dynamic adversarial inputs still use it, while replay checks reuse original exact envelope bytes. The future Worker producer must match these bytes; that cross-runtime proof is not implemented here.

`valid-*` vectors include all seven states; validity of a signed non-granting state never grants a start. `wrong-*` and `duplicate-escaped-key` vectors must refuse. Further malformed encoding, source-evidence, clock, replay and policy cases are generated in memory by the checks. Run `./scripts/verify-licensing.sh` from the repository root. Its executable launches no app and performs no network/Keychain/OS-clock work. Explicit development option `--emit-fixture-vectors` writes only under `.build/pat-2613-evidence/generated-vectors`; ordinary checks do not rewrite checked-in expectations. `--verify-fixture-corpus` verifies signatures and byte equality independently of the production verifier. Two separate assembler processes must emit identical bytes. Node is a preparation tool only, never a test or production runtime dependency.

The gate models manual, automatic and queued third-party starts only. It cannot deny discovery, update visibility, self-updates or safe recovery, and is not composed into an app. Its successful result is policy evidence only, never installer authority. Empty trust and missing state refuse. Replay and time are injected values with no persistence/authenticated transport implementation. Full restoration of an older valid local snapshot remains an admitted limitation: these checks do not prove tamper-proof storage, real monotonic time through sleep, boot identity or service ledger correctness. L2 and later operating proof own those boundaries.
