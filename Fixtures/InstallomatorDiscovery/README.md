# Offline Installomator discovery fixtures

PAT-2622 I1 is an injected, offline fixture model. These three `.sh` files are synthetic inert text, mode 0644, and must never be executed or sourced. The invented `.example.test` route, publisher and artifact bytes are test data. No upstream retrieval, Git authentication, descriptor-safe filesystem ingestion, native inspection, hosting, publication or installation is proved.

The original Apache licence bytes are read from the existing controlled repository fixture `ThirdParty/Installomator/LICENSE` and bound by the snapshot manifest's digest and length. That file, historical `source-provenance.json` and `References/Legacy/firefox.recipe.json` are unchanged. Original Installomator attribution is retained. The labels are marked synthetic modifications, not copies of an authenticated upstream tree. Optional notice payloads are independently bound in injected tests.

The four JSON files describe a complete synthetic inventory, separately supplied exact route policy, expected discovery events, and iteration scenario inputs. Tests read only these controlled repository files and the retained licence reference. All hostile variants are generated in memory; URLs and labels never become operations.

Each caller retains an independent expected checkpoint/state head across transitions, restart and batch changes. Explicit bootstrap requires both null state and null retained head. Hashes and complete structural revalidation detect inconsistency against that supplied head; a caller able to forge both history and head can forge continuity. This is not authenticated storage, rollback resistance, Git completeness or real filesystem race safety.

The parent independently observed meaningful Phase A red, accepted the API/schema and froze 13 original checks/helper/fixtures/gate files before explicitly releasing Phase B. The pure local implementation now passes the frozen focused checks and separate additive resource checks; parent acceptance, independent review and publication remain separate gates. Fixture admission has no `nativeEvidence` property and has `publicationAuthority: false`. Outputs are detached records, not assumed trustworthy because of object freezing. Callers may serialise or tamper their own copies; resumption revalidates them.

## Accepted standalone API

All exports are synchronous pure fixture functions. Closed key sets reject unknown fields and unsafe types. Only injected byte arrays are inspected; output byte retention is exact canonical base64. Plain serialized records are detached from inputs, and successful state transitions never edit earlier rows.

## Common values and canonical identity

- SHA-256: exactly 64 lowercase hexadecimal characters. Commit/tree: exactly 40 lowercase hexadecimal characters.
- Version, opaque attempt/batch/route/review identifiers: `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, <=64 ASCII bytes. Candidate IDs are deterministic SHA-256, not caller-selected opaque IDs.
- Reasons and review rationale: nonempty, <=1024 UTF-8 bytes. Evidence references: <=16 per observation/attempt, each `{ref,sha256}`, nonempty ref <=1024 UTF-8 bytes, digest lowercase64hex. No evidence reference is opened.
- `observedAt`, lengths and active milliseconds: nonnegative safe integers. Time must not regress across accepted history/checkpoints. `activeMilliseconds` is an independently injected incremental duration; no sleep/network wait is invented. Per-batch totals derive from immutable history, not caller counters.
- Canonical identity is SHA-256 of UTF-8 JSON with recursively lexicographically sorted object keys, arrays in their specified deterministic order, no whitespace; omit only the corresponding identity property. Tests implement this algorithm independently, without importing a production identity helper.
- Explicit first bootstrap requires null saved state, null independently retained expected head, and `bootstrap:true`. Expected-head keys are mandatory. Every later call requires validated complete saved data plus exact independently retained expected head and `bootstrap:false`. A caller who can forge both saved history and independent head can forge continuity. There is no authenticated persistence, durable CAS, rollback resistance or external authority in this model.

## literal-parser.mjs

`parseLabel({path,bytes,parserVersion})`

Return exact keys `{status,path,sha256,byteLength,bytesBase64,parserVersion,metadata,reason}`. Status `extracted` has `metadata:{name,type,downloadURL,claimedTeamID}` and reason null. Status `held` has metadata null and explicit reason. Valid supplied bytes <=1MiB are retained exactly even when grammar/encoding is held. Oversize input is held with reason oversized-not-retained, bounded byteLength and null sha256/bytesBase64 before digest/base64 allocation; the original oversized buffer remains caller-owned, with no truncation or exact-retention claim. Invalid non-byte inputs cannot claim a digest (nullable retention fields). Valid version-shaped strings name the caller's reviewed implementation revision, not grammar extensions.

Grammar is the existing literal grammar unchanged: exact fragments/labels ASCII basename and matching single arm, quoted four fields, no expansion/evaluation/escapes, full-line comments only; nonempty literals; UTF-8 fatal decoding; no BOM/bare CR/forbidden controls; tab only as indentation; <=256 logical lines (a final terminator does not create an additional blank line); <=1MiB label; name<=128 UTF8 bytes; type dmg/pkg/zip; ten uppercase ASCII alphanumeric claimedTeamID; raw syntactically absolute explicit `https://` URL <=2048 UTF8 bytes, no raw authority/userinfo delimiter or fragment marker, including empty authority `@`/fragment `#` cases. An @ in path/query is inert and permitted. Preserve raw URL spelling. No WHATWG repair, URL canonicalisation or network-safety claim.

## snapshot.mjs

`ingestSnapshot(input,options)`

- Input keys `{manifest,payloads,licenseBytes,noticePayloads}`.
- Options keys `{previous,expectedCheckpointId,bootstrap,parserVersion,policyVersion,repair}`.
- Manifest keys `{schema,repository,commit,tree,parentCommit,priorCheckpointId,parserVersion,policyVersion,observedAt,complete,inventory,license,notices,attribution}`.
- Manifest schema `fixture-snapshot-v1`, repository exactly `Installomator/Installomator`, complete exactly true. ParentCommit/priorCheckpointId null only bootstrap, otherwise exact previous commit/ID for a next revision.
- Inventory descriptor keys `{path,kind,ancestors,sha256,byteLength}`; kind regular; ancestors exactly `[{path:'fragments',kind:'directory'},{path:'fragments/labels',kind:'directory'}]`. Path exact `fragments/labels/<ASCII basename>.sh`, <=1024 UTF8 bytes for inventory, payload and checkpoint label paths. Snapshot/checkpoint canonical metadata, including retained base64, is capped at128MiB. Preflight counts bounded JSON-shaped traversal, depth and escaped string sizes incrementally before copying or canonical hashing; it does not first construct an oversized serialised string. At most32 traversal levels and1000000 visited values are accepted. These are standalone fixture resource limits, not filesystem or production protocol claims. No traversal, duplicate, case-fold collision, ambiguous separator, symlink or other kind.
- Payload keys `{path,bytes}`; exact one-to-one inventory/file set. At most10000 labels, 1MiB each, total32MiB. Bounds checked before decoding/copying as applicable; recompute every digest and byteLength.
- License descriptor keys `{path,sha256,byteLength}`, path exactly LICENSE, bytes <=1MiB. Notice descriptors same keys, safe basename `NOTICE` or `NOTICE-<ASCII identifier>`, <=16 unique notices each <=1MiB. Notice payloads `{path,bytes}` match exactly. Attribution is nonempty bounded string (<=1024 UTF8 bytes). Original controlled licence reference and attribution remain unchanged; this does not authenticate an upstream licence/tree.
- Repair null or `{component,fromVersion,toVersion,reviewId,rationale}`, component parser or policy. Exactly one changed component per reviewed repair; from/to must match previous/current versions. This is injected review metadata, not verification of a real reviewer's authority.
- Return keys `{status,checkpoint,reason,nextAction}`. Complete status `complete`, reason/nextAction null. Duplicate status `duplicate` retains original previous checkpoint exactly; does not refresh its observedAt. Refusal status `refused` retains prior state and explicit bounded reason/nextAction.
- Checkpoint keys `{schema,scope,repository,commit,tree,parentCommit,priorCheckpointId,parserVersion,policyVersion,observedAt,inventory,labels,license,notices,attribution,repair,checkpointId}`. Schema `fixture-checkpoint-v1`, scope fixture-only. Inventory and labels sorted by path. All labels classified, including held labels. Labels are parser return records; license/notices retain descriptor keys plus bytesBase64. No complete flag is needed in a constructed complete checkpoint. checkpointId independently covers every other field.
- Revalidate complete previous checkpoint, content/digests/classifications, versions and identity before accepting. Duplicate same commit is allowed only with identical source bytes/inventory/licence/notices/provenance versions; observation delivery time may be later but does not replace old checkpoint. Changed source under same commit refuses, even during a reviewed repair. Explicit reviewed same-commit reclassification requires exact source repository/commit/tree/inventory/bytes/licence/notices/attribution; parentCommit retains the previous source parentCommit, priorCheckpointId links the previous classification, observedAt retains original source observation time even if a later delivery time is supplied. A new checkpoint ID binds the new version, repair and prior classification. Never invent a self-parent Git commit. Stale prior commit, backwards time, wrong predecessor, incompatible versions or absent/corrupt expected baseline refuses.

## diff.mjs

`diffSnapshots(previous,current)` -> `{status,events,reason}`. First previous may be null; otherwise checkpoints must validate and current must be exact duplicate or successor. `status:'compared'` has null reason and sorted events; `refused` has empty events and reason.

Event exact keys `{kind,path,previousSha256,sha256,previousBytesBase64,bytesBase64,invalidateAcceptance,removeApprovedSupport,publicationAuthority}`. Kinds added, changed, withdrawn-upstream. Nonexistent side fields null. Changed/withdrawn set invalidateAcceptance true; added false. removeApprovedSupport and publicationAuthority always false. No nativeEvidence property. Identical label content across commits or duplicate delivery with unchanged relevant versions emits no events. Reviewed parser/policy version changes or changed classification emit changed facts with invalidateAcceptance true for all affected labels, retaining identical previous/current raw digests/bytes when source bytes are unchanged. This represents reclassification, not new upstream data; iteration bindings independently prevent stale evidence reuse. Unchanged unrelated evidence is not discarded.

## candidates.mjs

`buildCandidate(checkpoint,labelPath,policy)` -> `{status,candidate,reason,publicationAuthority}`. `candidate` status with nonnull candidate and null reason; `held` with candidate null and bounded reason. publicationAuthority always false.

- Policy keys `{schema,version,routes}`, schema fixture-route-policy-v1, version must equal checkpoint policyVersion. route list bound<=10000 and unique route IDs and label paths. Empty policy admits none.
- Route keys `{routeId,version,labelPath,name,type,downloadURL,claimedTeamID,channel,artifactSha256,artifactByteLength}`. Channel exactly stable. Every label metadata field/path must match exactly; no normalization. Changed/new trust remains `route-review-required`. Route input is supplied independently of label input; no upstream assertion approves itself.
- Candidate keys `{schema,scope,candidateId,repository,checkpointId,commit,tree,labelPath,labelSha256,labelByteLength,labelBytesBase64,parserVersion,policyVersion,route,publicationAuthority}`. Schema fixture-candidate-v1; scope fixture-only. candidateId SHA-256 of UTF8 repository + newline + exact labelPath. Same stable candidate across revisions and batches retains lifetime cap. Candidate validation rechecks raw label bytes/digest/parser metadata and exact route match; no unauthenticated constructor asserts native trust. Fixture artifact bytes bounded <=32MiB, expected length same limit; this is a standalone fixture ceiling, not a real download policy.

`verifyCandidate(candidate,observation)` -> `{status,reason,evidence,publicationAuthority}`. `fixture-admitted` has null reason and evidence; `held` has explicit reason and null evidence. Never includes nativeEvidence. Wrong publisher => publisher-mismatch; recomputed artifact digest or length mismatch => artifact-mismatch; unavailable => capability-unavailable; nonpassing checks => verification-failed. Unknown/invalid input never admits.

- Observation keys `{schema,checkerVersion,environmentVersion,capabilityVersion,availability,artifactBytes,observedPublisher,checks,evidenceRefs}`, schema fixture-observation-v1. Availability available/unavailable; checks exact `{signature,notarisation,container,compatibility}` values passed/failed/unknown/unavailable. Every check must be passed and exact observedPublisher must match route. Injected passed strings are only fixture results, never OS validation. Unavailable observations may still carry known fixture bytes, as the tests do; absent unknown observations remain held.
- Evidence keys `{bindingSha256,artifactSha256,artifactByteLength,checkerVersion,environmentVersion,capabilityVersion,evidenceRefs}`. binding canonical fields `{repository,labelPath,labelSha256,parserVersion,policyVersion,route,checkerVersion,environmentVersion,capabilityVersion,artifactSha256,artifactByteLength,observedPublisher,checks,evidenceRefs}`. Actual artifact digest/length, observed publisher, exact checks and evidence refs are bound alongside versions. Route includes expected hash/length; actual artifact is independently recomputed before admission. Commit/checkpoint/time are provenance but excluded from reuse binding because an unrelated upstream commit must not refresh unchanged acceptance.

## attempts.mjs

`advanceAttempt({state,expectedStateId,bootstrap,batchId,attemptId,candidate,observation,observedAt,activeMilliseconds,retry})`

- Return keys `{status,state,attempt,reason,nextAction}`. `recorded`: a new copied append-only history row/state, nullable success reason/nextAction; attempt holds fixture-admitted or held verification outcome. `reused`: exact old accepted row and unchanged state, no freshness update. `held`: no new attempt, unchanged state, reason and nextAction. `refused`: malformed/inconsistent input/state, no attempt, unchanged supplied state, reason/nextAction. Refused oversized input need not be copied; no successful immutable output is constructed from it.
- State keys `{schema,scope,history,batches,stateId}`, schema fixture-attempt-state-v1, scope fixture-only. Complete structural/outcome/digest/counter/link revalidation and retained head comparison before transition. JSON roundtrip restore is supported.
- Row keys `{attemptId,candidateId,batchId,priorAttemptId,observedAt,activeMilliseconds,candidate,observation,retry,outcome,reason,evidence,publicationAuthority}`. `candidate` is complete candidate object. Saved observation replaces artifactBytes with artifactBytesBase64, otherwise exact same keys. PriorAttemptId is last attempt for that candidate, null only its first attempt. Outcome fixture-admitted/held. Reason null for admitted; explicit for held. publicationAuthority false; no nativeEvidence. Evidence and retry retained exactly. Unique attempt IDs global; stable candidate IDs recomputed from repository/path.
- Batch keys `{batchId,candidateIds,activeMilliseconds,firstObservedAt,lastObservedAt}`. Batches ordered first-seen; candidateIds unique first-seen; totals/times recomputed from rows. No trusting caller-reset counters. Starting a new batch permits another ten independent candidate identities/30 active minutes but cannot reset any candidate's three lifetime attempts. An unfinished (last outcome held) candidate remains charged to its originating batch even when the request names another batch; resolve effective batch before applying limits. Exhausted originating active time returns active-time-limit. The original batch association is derived from history, never caller-reset. Reusing an old batch ID retains its original counters.
- Retry null for first/new upstream bytes or changed accepted binding after a prior pass; explicit alternatives: reviewed repair `{kind:'reviewed-repair',component,fromVersion,toVersion,reviewId,rationale}` component parser/checker/policy/environment; restored capability `{kind:'restored-capability',fromVersion,toVersion}` after capability-unavailable; independent route review `{kind:'route-review',fromVersion,toVersion,reviewId,rationale}` with changed policy and route version, after trust mismatch. No generic repair/restoration retries a trust mismatch. Review markers describe injected fixture decisions, not real authority. Version-only changes cannot spin failed inputs. Changed upstream bytes can retry non-trust failure, preserving lifetime cap.
- Work-hold reasons tested: unchanged-failure, retry-not-authorised, route-review-required, attempt-limit, candidate-limit, active-time-limit. Validated malformed state/inputs refused; saved-state bounds refused with state-limit before cloning/hash where possible.
- Max10 distinct candidates per batch; max3 recorded attempts per stable candidate across history/batches; max1800000 active milliseconds per batch inclusive. Zero active work allowed for unavailable checks; negative/unsafe/fractional time refuses. Cap exhaustion cannot manufacture a pass. Unchanged passed observation may reuse only after validating actual current observation/bytes and all relevant bindings, never mask tamper or unavailability. After a pass, invalid changed publisher/artifact/check outcomes/unavailable observations must append a held observation with no new accepted evidence, preserving the old passed row only as history. Valid changed evidence refs or ref digests require full fixture reverification and a NEW fixture-admitted row with a changed bindingSha256 and linked priorAttemptId; never reuse or mutate the old evidence. Unchanged trust policy and otherwise valid observations require no owner review merely for new injected fixture evidence. All normal attempt/batch limits still apply.
- Saved caps: <=10000 stable candidates, <=30000 rows, <=1000 batches, <=16MiB canonical encoded UTF8. No eviction/reset to make room. Fail with next action on exhaustion. Individual IDs/refs/rationale/reasons retain common limits. Checks include oversize state arrays/strings and retained-head loss/reforgery/replay.


## Local acceptance and limits of proof

The focused gate contains the original 188 frozen tests; always-refuse cannot pass its extraction, routing, fixture-admission and iteration positives. Four separately added resource cases cover exact path boundary, giant metadata and recursive/accessor refusal, including incremental escaped-string byte accounting. No frozen assertions were changed after Phase B release. The first implementation run passed187/188; its sole failure was an unnecessary JS freeze on a returned checkpoint that the corruption test deliberately edits. Returning a detached checkpoint restored intended corruption/revalidation coverage. Local checks now pass; parent full-diff acceptance, independent review and publication remain required.

A valid changed evidence reference or digest does not automatically hold and cannot reuse old evidence: it must reverify exact artifact/publisher/checks into a fresh linked admitted row with a different binding. Invalid changed observations append held rows with no accepted evidence. All normal budgets still apply. This distinction was settled before the checks were frozen.

No snapshot or model result proves real filesystem race safety, authenticated Git completeness/ancestry, actual review-principal authority, native publisher/notarisation checks, durable anti-rollback, operating service, release signing, publication or installation. The finite lifetime three-attempt cap is local fixture-work policy; new release-job semantics for a production feed require future explicit acceptance.

The in-process input model is ordinary JSON data-descriptor records and caller-supplied nonshared fixture byte buffers. Validation avoids invoking data getters or toJSON on those records. It does not sandbox arbitrary hostile JavaScript Proxies or typed-array subclasses already executing inside its own process. No filesystem, network, process, dynamic-loader, VM or shell-evaluation operations are implemented.
