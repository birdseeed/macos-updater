# Update preferences private fixtures

PAT-2662 Phase A, 14 October 2026. These are synthetic principal/product/release inputs, not installed identity, authentication or installation authority. `records.json` is one exact canonical empty schema-1 record with no trailing newline. The independent check encoder must match those literal bytes before behaviour checks count.

Wire fields are exactly `exclusions`, `mutations`, `principal`, `revision`, `schema`, `skips`, `storeScope`. JSON object keys sort lexically, no whitespace or trailing newline, literal UTF8 strings, unescaped forward slashes and decimal unsigned integer tokens. Schema is integer 1; revision is UInt64. Reject unknown or duplicate fields, invalid UTF8, noncanonical escapes/order/numbers, partial records, duplicate array identities and duplicate mutation IDs. Canonical re-encoding must equal input exactly, after strict closed/typed validation. Exclusion arrays and skip arrays sort by lexicographic canonical object bytes. Mutation history preserves append order.

Exclusions contain exactly channel/edition/product/scope. Skips contain exactly artifact/build/channel/edition/product/release/scope. All opaque identity strings, including principal, storeScope, app/release components and mutation IDs, are nonempty, at most 256 UTF8 bytes, and contain no NUL/control characters. A record has at most 1,048,576 bytes, 256 exclusions, 512 full skips and 128 mutation receipts. Do not silently evict history. An accepted edit increments revision once, even if its exact change is already represented; a retained identical mutation ID+operation replays the currently accepted revision without any write, even with its original stale expectedRevision. The same ID with another operation conflicts.

A mutation receipt is exactly `id` and `operation`. Operation is an encoded string containing independently closed, typed, canonical JSON, at most 4096 UTF8 bytes: exclusion has exactly action="exclusion", app={channel,edition,product,scope}, excluded=JSON boolean; skip/undo has exactly action="skip" or "undo" and release={artifact,build,channel,edition,product,release,scope}. No opaque arbitrary JSON is accepted. Under these field bounds a valid operation is below 4096 bytes; the 4096/4097 malformed-string controls establish refusal, and maximal valid identity records establish the reachable positive boundary. Nested objects obey the same strict canonical validation.

Tests own all store mechanics. MemoryStore is a deterministic serial fake CAS with explicit lost acknowledgement/readback faults. OwnedStore exclusively creates a canonical `.build/update-preferences-checks-UUID` directory (0700), uses directory-relative no-follow regular-file reads, same-owner/single-link/mode-0600 records, bounded reads and exclusive same-directory temporary files. It syncs the temporary file, renames then syncs the directory. Failure before rename is known-not-committed; uncertainty after rename is never acknowledgement. Injected short-write/sync/rename failures prove selected fixture failure handling, not physical crash/hardware durability. Exact previous bytes are checked serially; this is not adversarial atomic CAS against a malicious same-user process. No path can be supplied externally. Reopening takes only a live owned fixture and checks its device/inode/owner/mode. Cleanup unlinks exact owned names and requires the original directory identity; it never recursively removes unknown content.

No app/helper/window launch, network, real user preferences, UserDefaults, Keychain, installation, productive identity or durable queue format is used. Pure QueueModel starts/completions are model transitions only. Queue snapshots are not serialised. Fixture process/session reconstruction is not native app relaunch evidence.
