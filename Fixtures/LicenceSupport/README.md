# Pure licence support fixtures (PAT-2616 P1)

The pure P1 reference mechanics are implemented locally. Run `./scripts/verify-licence-support.sh`. Before implementation, the parent independently observed the compiling Phase A red: 218 cases, 210 refusing-stub failures and eight default/closed-action passes, then explicitly released Phase B. The focused gate passes 249 cases, including 31 additive hardening cases, and the full `./scripts/verify.sh` gate passes. A compiling mutation that removed the independent ownership-judgement guard failed its necessary ownership assertion; the exact original source bytes were restored. Parent verification, independent review and publication remain acceptance gates. The ordinary `RefusingSupportClient` permanently refuses every lookup, prepare and commit. All positive transitions are accessible only through explicit `@_spi(Testing)` input. Fake identities and concrete fixture clients belong only to the checks.

No parser result, digest, presentation or injected judgement authenticates an operator, establishes a human's ownership, authorises a service call, or permits installation. SHA-256 provides exact-byte binding, not an authenticated server assertion. This target has no dependency on licensing, activation, Core, a service, storage, network, native keys, mail, a provider or app composition. No real identity or customer data belongs in these fixtures. P2 presentation UI, P3 service/authentication/provider work and H7 adequate recovery ownership evidence remain separate.

## Independent vectors and red freeze

`vectors/*.json` contain a `name`, exact UTF-8 descriptor/case `bytes` string and independently calculated `sha256`. They were generated using Python's standard `json`, `hashlib` and `base64`, with ordered literal dictionaries and a fixed public fixture nonce. Production parsing/digest code was never called. The generator and Phase A run evidence live privately under `.build/pat-2616-evidence`. Swift checks calculate their own expected hash with CryptoKit and mutate the checked bytes independently; ordinary gate runs never regenerate vectors. These are public synthetic references, not signed/authenticated assertions.

The confirmation domain is `im.patched.support.confirm.v1` plus one NUL plus original descriptor bytes. The recovery domain is `im.patched.support.recovery.v1` plus one NUL plus original deterministic case bytes. The note hash is plain SHA-256 over the decoded note's exact NFC UTF-8 bytes. Escaped Unicode can produce a different descriptor digest with the same decoded note digest. Decomposed notes must be rejected by byte comparison with NFC, since Swift string equality treats canonical equivalents as equal.

The checks deliberately include positive confirmations, state transitions and complete recovery effects so universal refusal cannot pass. Snapshot comparisons require rollback to restore the entire model, including its claim. Phase A frozen hashes are recorded in `.build/pat-2616-evidence/phase-a-sha256.txt`. **CHECK-MODIFIED (additive only):** Phase B adds `HardeningChecks.swift` and exactly one registration call in `main.swift`; all original assertion bodies and all seven vectors are unchanged. `phase-b-frozen-integrity.txt` verifies those original bytes, removing only the new registration line before comparing the main-file hash. No check defect or weakened assertion was needed. Future changes must preserve those bodies/vectors or explain a real check defect to the parent; additive cases are permitted.

## Local reference assumptions (not a live service contract)

The parent accepted the following bounded local choices where support sections 3/6/7/9/10 leave wire detail open. Real integration must separately reconcile provider shapes and identity/evidence standards. All JSON objects are ordered and closed; unsigned decimal integers use the L1 range 0...9,007,199,254,740,991. Revisions are positive. Descriptor/case input is at most 4,096 bytes and depth 5 (root included). Times and checked arithmetic stay in that exact range. All strings reject controls, bidi format controls and invalid Unicode; opaque IDs are lowercase ASCII hex.

## Pure transaction and recovery model boundary

The SPI ledger holds effect/dependent counts, a minimal audit and terminal outcome, bound to the exact request ID, operator ID and descriptor digest. Each ledger is explicitly scoped to one prepared request; cross-request nonce storage and service-wide single-flight are P3 work, not provided by this in-memory value. It models section 7's claim/effect/dependent/audit/terminal atomic result, not SQL, dispatch, provider outcomes or remote concurrency. Synthetic interleavings/repeats prove at most one effect for that in-memory request. The same bound request, operator and digest may read its terminal result after expiry; changed operator/digest cannot. Stale account/entitlement/target produces audited terminal `targetChanged`; missing effect with no changed guard, missing dependent/audit, and unmatched completion roll back. A lost readback may leave a committed row and is resolved only by that row. No model outcome represents a confirmed refund or cancellation.

`SupportFixtureContext.kind == operatorFixture` is an explicit test seam, never a deployable role. The ordinary model refuses email change; `RecoveryFixtureModel` adds necessary checks and commits through the same transaction model. Session IDs, confirmation request/digest and human confirmation bind fixture transitions. The prepared session ID is injected trusted fixture state, not recovered or authenticated from the descriptor. No caller-supplied pair of IDs validates an assertion or proves a human signed in. Consumer, verified-household, restricted purchase, checkout email, receipt and provider payment contexts cannot acquire operator authority.

Routine recovery additionally requires an independently injected ownership judgement matching the case's opaque reference, mapped source evidence, active-Mac possession for the exact case digest, new-email proof bound to exact account/case/digest/new-email and purpose `email-recovery`, and proof current at commit. All source/possession/new-email/ownership reference pairs and the kind must match between the case and confirmation. `sourceVerified` and `betaInvitationVerified` are trusted injected corroboration for the exact account and source kind, not independent record lookups performed by this model. Possession and new-email proof bind the exact case digest; opaque references never verify a real identity. Accepted notice must be bound to that digest and commit must be strictly after acceptedAt + 259,200; arithmetic overflow and future times refuse. No acceptance timestamp, ambiguous acknowledgement, bounce, objection or dispute holds. Collision is checked again at commit and never merges accounts. Exceptional lost-email/all-Macs recovery always refuses pending H7.

Recovery atomically changes only the opaque email binding/shared account revision, revokes all sessions, advances every occupied activation revision and empties slots. Account ID, entitlement revision, trial, beta and paid history persist, and no session/key/lease is minted. The existing L2 cache-block and A1 released-activation tests own their unchanged runtime-model consequences; this slice does not reimplement those clients. Actual possession authentication, ownership standards, notices, native UI, D1 rollback/concurrency, real storage and service/provider mutations remain unimplemented.
