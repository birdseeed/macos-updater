# Pure scheduling fixtures

PAT-2612 introduces the narrow H1 pure policy and queue starter. Run
`./scripts/verify-scheduling.sh` from any directory. The script builds the check
executable and runs it from the repository root. `policy-vectors.json` is consumed
by `TimingChecks.swift`; each row asserts the pause decision for a deadline of UTC
200, anchored at UTC100 / monotonic10 in boot-A. Values are synthetic whole seconds,
not real dates or observations. Additional timing, identity and queue checks use
in-memory values. Checks never launch an app or inspect installed apps.

The parent recorded the compiling Phase A refusing-stub red result before authorising
implementation. The allowed automatic case prevents an always-refusing implementation
from passing. The gate also checks automatic opt-out, exclusions, UTC pause, exact
skip/repack behaviour, fresh timing and safety inputs, and queue recovery/isolation.

Opaque principals, verified-identity declarations, current eligibility and clocks
are injected fixtures, not authenticated receipts. A positive model decision gives
no installation authority. Queue snapshots model reconstruction in memory, not a
safe persistence format or evidence of crash/power-loss durability. The scheduler
has no OS, network, storage or transaction adapter and is not composed into an app.

Clock samples use whole seconds. Same-boot UTC and monotonic elapsed seconds must
match exactly; this intentionally conservative fixture contract defers clock jumps
or inconsistent sleep clocks. New boot samples require trustworthy UTC. Current
eligibility must already cover fresh trust, entitlement, installed identity, route,
power and session safety, including re-anchored eligibility after reboot. The pure
module does not verify those facts, authenticate principals or grant capabilities.
Manual unattended starts ignore automatic pause/awake/idle controls but require
fresh eligibility and a closed target. Restart/interactive/unknown routes remain
for attention until a separately authorised consent flow exists.

Skip identity is product/scope/release/build/edition/channel/artifact, independent
of catalogue metadata revision. A different build or artifact under the same
skipped release is ambiguous; a distinct verified release is reconsidered using
fresh eligibility, which owns release ordering and prerequisite checks. Exclusions
use the injected stable product key.

Each logical queue lifetime needs a distinct injected queue ID, retained in its
snapshot with principal, attempt sequence, successful request IDs and safety barrier.
Current inputs bind the exact target and release. Snapshots are generated by the
model and have no public constructor or decoder. Reconstruction turns running work
into recovery; duplicate/stale/foreign replies fail. Only a verified isolated
rollback permits subsequent independent work. Shared or uncertain failure retains
an attention barrier even after reconstruction or an isolated rollback claim.
There is no API that clears that barrier or retries a terminal entry. Unstarted
work remains pending under refusal and rechecks current policy at each start.
